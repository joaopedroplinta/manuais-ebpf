\chapter{Pré-requisitos}\label{cap:prerequisitos}

Este capítulo lista o que é necessário saber e instalar antes de seguir o manual, e como verificar se a máquina está pronta. Os comandos foram pensados para Ubuntu, a distribuição usada no minicurso. Em outras distribuições os nomes dos pacotes mudam, mas as ferramentas e os requisitos de kernel são os mesmos.

\section{Conhecimentos necessários}

Não é preciso saber programar para o kernel, mas alguns conhecimentos são assumidos:

\begin{itemize}
  \item uso confortável do terminal Linux, de \texttt{sudo} e do gerenciador de pacotes da distribuição;
  \item noção de processo, chamada de sistema (\textit{syscall}) e da separação entre espaço do usuário e kernel;
  \item leitura básica de C, suficiente para acompanhar os exemplos de \textit{struct}, ponteiros e funções;
  \item noções de rede (TCP, portas) e de métricas de sistema (CPU, memória, I/O), úteis nos exemplos práticos;
  \item familiaridade com \texttt{/proc}, por exemplo \texttt{/proc/stat} e \texttt{/proc/net/dev}. Não é obrigatória, mas ajuda a entender por que o eBPF é uma alternativa.
\end{itemize}

Quem já escreveu um módulo de kernel ou usou \texttt{perf} e \texttt{strace} vai reconhecer vários conceitos, mas nada disso é exigido.

\section{Ferramentas necessárias}

\begin{itemize}
  \item \textbf{Kernel Linux 5.4 ou superior}, com BTF habilitado (\texttt{CONFIG\_DEBUG\_INFO\_BTF=y}). Para os recursos mais novos, como o \textit{ring buffer}, prefira o 5.8 ou superior. A maioria das instalações Ubuntu 20.04 ou mais recentes já atende.
  \item \textbf{Permissão de superusuário} (\texttt{root}) para carregar programas no kernel. A partir do kernel 5.8, as capacidades \texttt{CAP\_BPF} e \texttt{CAP\_PERFMON} permitem fazer isso sem \texttt{root} completo \cite{linuxkernel2024}.
  \item \textbf{clang e LLVM}, que compilam o C para \textit{bytecode} eBPF.
  \item \textbf{libbpf e libelf}, para carregar e gerenciar os programas.
  \item \textbf{bpftool}, para inspecionar programas e mapas carregados e gerar o cabeçalho \texttt{vmlinux.h}.
  \item \textbf{bpftrace} e \textbf{libbpf-tools}, para consultas rápidas e ferramentas prontas. O \textbf{BCC} é opcional (capítulo \ref{cap:ferramentas}).
  \item \textbf{Docker}, opcional, para os exemplos com contêineres.
\end{itemize}

Além do BTF, o kernel precisa ter o suporte a eBPF e a instrumentação compilados. As opções \texttt{CONFIG\_BPF}, \texttt{CONFIG\_BPF\_SYSCALL}, \texttt{CONFIG\_BPF\_JIT}, \texttt{CONFIG\_BPF\_EVENTS}, \texttt{CONFIG\_KPROBES} e \texttt{CONFIG\_UPROBES} devem estar com valor \texttt{y}, o que é o padrão nas distribuições comuns. Três sistemas de arquivos também são usados: \texttt{/sys/fs/bpf} (para fixar objetos), \texttt{/sys/kernel/tracing} e \texttt{/sys/kernel/debug}. Normalmente já vêm montados.

\section{Instalação e configuração do ambiente}

Primeiro, verifique se o kernel atende aos requisitos:

\begin{lstlisting}
uname -r
ls /sys/kernel/btf/vmlinux
grep CONFIG_DEBUG_INFO_BTF /boot/config-$(uname -r)
\end{lstlisting}

O segundo comando deve listar o arquivo sem erro, e o terceiro deve retornar a linha \texttt{CONFIG\_\allowbreak DEBUG\_\allowbreak INFO\_\allowbreak BTF=y}. Se o arquivo não existir, o kernel não expõe BTF e os programas CO-RE deste manual não vão carregar. Para conferir as demais opções de uma vez:

\begin{lstlisting}
grep -E '^CONFIG_(BPF|BPF_SYSCALL|BPF_JIT|BPF_EVENTS|KPROBES|UPROBES)=' \
    /boot/config-$(uname -r)
\end{lstlisting}

Em seguida, instale as dependências:

\begin{lstlisting}
sudo apt update
sudo apt install -y clang llvm libbpf-dev libelf-dev \
    linux-tools-$(uname -r) \
    linux-headers-$(uname -r) \
    bpftrace libbpf-tools python3 python3-pip
\end{lstlisting}

O pacote \texttt{libbpf-tools} instala as ferramentas prontas do capítulo \ref{cap:monitoramento}, com o sufixo \texttt{-libbpf} (por exemplo, \texttt{execsnoop-libbpf}). O BCC, instalado pelo pacote \texttt{bpfcc-tools} e com o sufixo \texttt{-bpfcc}, é opcional e pode falhar em kernels muito recentes, como descrito em \textit{Problemas comuns}.

O pacote \texttt{linux-tools} traz o \texttt{bpftool}. Com ele, gere o cabeçalho com todos os tipos do kernel em uso, que os programas em C incluirão no lugar dos cabeçalhos tradicionais:

\begin{lstlisting}
bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h
\end{lstlisting}

O arquivo gerado tem mais de cem mil linhas e deve ser regenerado quando o kernel for atualizado. Em seguida, confira se o \texttt{bpftool} enxerga o sistema com \texttt{sudo bpftool prog show}, que lista os programas eBPF já carregados (o sistema costuma ter alguns, do \texttt{systemd}, por exemplo).

Para confirmar que tudo funciona, rode um programa mínimo de \texttt{bpftrace} que conta as chamadas \texttt{openat} por processo. Deixe-o rodando alguns segundos e encerre com \texttt{Ctrl+C}, que imprime o mapa acumulado:

\begin{lstlisting}
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat { @[comm] = count(); }'
\end{lstlisting}

Se a saída listar nomes de processos com suas contagens, o ambiente está pronto.

\subsection*{Problemas comuns}

\begin{itemize}
  \item \texttt{Operation not permitted}: o comando precisa de \texttt{root}. Repita com \texttt{sudo}. Sem ele, até o \texttt{bpftool prog show} falha. O parâmetro \texttt{kernel.unprivileged\_bpf\_disabled}, que pode ser consultado com \texttt{sysctl}, define se usuários comuns podem carregar programas, e em muitas distribuições vem desabilitado.
  \item \texttt{/sys/kernel/btf/vmlinux} inexistente: o kernel não foi compilado com BTF. Atualize para um kernel mais novo da distribuição.
  \item Cabeçalhos ou \texttt{bpftool} de outra versão: depois de atualizar o kernel, reinstale \texttt{linux-tools} e \texttt{linux-headers} para a versão de \texttt{uname -r}.
  \item \texttt{Failed to compile BPF module} em uma ferramenta \texttt{-bpfcc}: o BCC compila o programa na hora, contra os cabeçalhos do kernel, e versões mais antigas do BCC não acompanham kernels muito recentes. Use a versão \texttt{-libbpf} da mesma ferramenta, ou um \textit{script} de \texttt{bpftrace}.
  \item Erro do \texttt{bpftrace} sobre o \textit{tracepoint}: confira o kernel e se o \texttt{/sys/kernel/tracing} está montado.
  \item Máquinas virtuais e WSL: nem todas as imagens trazem um kernel com BTF e \textit{tracepoints}. Em caso de dúvida, rode as verificações acima antes de seguir.
\end{itemize}
